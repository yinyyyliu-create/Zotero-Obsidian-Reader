# Zotero to Obsidian bilingual reader

Use the title, DOI, or Zotero Item Key as the paper identifier. If the identifier is missing or ambiguous, resolve it with the user before processing a PDF. Course defaults to 学术论文精读. On this Windows setup the active vault has been `your Vault`. Verify the directory for the current request and honor a different destination specified by the user.

1. **Resolve the source.** Use the configured Zotero MCP if it can find the exact item and expose the PDF. On Windows, run [find-paper.ps1](scripts/find-paper.ps1) with `-Identifier '<title or DOI>'` or `-ItemKey '<key>'`. The helper sends GET requests to the local Zotero API with `curl.exe --noproxy '*'` and locates imported PDFs under the active or configured data directory. If a sandbox blocks the loopback and Zotero is running, retry the same GET via the allowed host approval path. Use only the matched item and verify the PDF's title, DOI or other metadata and first page. Resolve conflicting editions or attachments before proceeding. Stop if the intended item or PDF cannot be obtained. Keep Zotero read-only.
2. **Map the entire PDF.** Record page count and heading hierarchy. Assign stable page-linked IDs to source paragraphs, captions, and references, including continuations. Follow the [extraction and assembly reference](references/assembly.md) for multi-column layout, formulas, and the generator manifest. Check the extraction against the complete PDF before claiming full coverage.
3. **Translate and annotate in batches.** Write adjacent English and Chinese for all extractable prose. Preserve citations, wording of limitations, units, formulas and quantities. Translate captions and reference titles while retaining original bibliographic records. Annotate each prose paragraph in Chinese with its function, relation to surrounding argument, evidence or assumptions and inference limits, and a research implication. Anchor every overall claim to source blocks. Flag missing or uncertain material at its source location. Use the five categories on selected exact English spans, with green for genuine concessions, qualifications or rebuttals supported by the text.
4. **Build the deliverables.** Assemble the ordered manifest following [assembly.md](references/assembly.md). Run [build_reader.py](scripts/build_reader.py) against the verified PDF. The bundled HTML template includes offline rendering, the 65/35 responsive layout, print styles, stable personal highlights, notes, section bookmarks, progress, search and filter, JSON backups with validation, Markdown export, and confirmed reset. The generated Markdown includes YAML metadata, argument analysis, research questions, and relative HTML and Zotero links. No personal state is written back into HTML.
5. **Test and archive.** Check counts, ID uniqueness, visual integrity, translations, links, and offline interactions in a browser. Create `Literature/HTML` and `Literature/Notes` in the selected vault when requested. Archive the completed HTML and Markdown together using a shared stem and verify the relative link and both copied files. Keep existing user files intact. If a stem collides, generate a new paired stem or follow the user's explicit replacement instructions. Respect actual workspace write permissions and use normal approval for vault writes when needed.
6. **Report.** Give actual absolute archive paths, title, item and PDF keys, pages, numbered headings, prose and translation counts with scope, figures/tables/formulas/references, tests completed, and extraction gaps or unavailable external supplements. Distinguish a partial reader from a complete one. Never silently stop after the first pages.
